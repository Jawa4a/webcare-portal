# Установка и обновление

## Требования

- Docker Desktop или Docker Engine с Compose v2;
- не менее 2 ГБ свободной памяти;
- свободные порты `3000`, `8080`, `5432` либо собственные значения в `.env`.

Java, Maven, Node.js и PostgreSQL на хост устанавливать не требуется: сборка выполняется внутри контейнеров.

## Первый запуск

1. Запустите окружение из корня проекта:

```bash
docker compose up --build -d --wait
```

2. Откройте <http://localhost:3000>.
3. Проверьте состояние:

```bash
docker compose ps
```

Все три сервиса должны иметь статус `healthy`. Flyway автоматически создаёт или обновляет схему до последней версии; Hibernate только проверяет соответствие сущностей схеме.

## Настройка

Дополнительная настройка для локальной демонстрации не требуется. Чтобы переопределить стандартные параметры, скопируйте `.env.example` в `.env` и измените необходимые значения:

- порты frontend, backend и PostgreSQL;
- пароль базы;
- параметры стартовых учётных записей;
- сетевые тайм-ауты и лимиты аудита;
- `SESSION_COOKIE_SECURE=true` для HTTPS.

`AUDIT_ALLOW_PRIVATE_ADDRESSES` должен оставаться `false`. Значение `true` используется исключительно файлом `compose.test.yaml` в изолированной сети.

## Обновление

После получения новой версии исходного кода:

```bash
docker compose build
docker compose up -d --wait
```

Миграции применятся до запуска API. Именованный том PostgreSQL сохраняется при пересоздании контейнеров.

## Остановка

```bash
docker compose down
```

Команда не удаляет данные. `docker compose down --volumes` безвозвратно удаляет локальную базу и применяется только при явной необходимости начать с нуля.

## Развёртывание вне локального компьютера

Для внешнего сервера используйте `compose.prod.yaml`. Он добавляет Caddy, включает защищённые cookie, требует явные пароли и не публикует порты backend и PostgreSQL. Пошаговая настройка VM, DNS, HTTPS, запуска и резервного копирования описана в [руководстве по публичному развёртыванию](deployment.md).
