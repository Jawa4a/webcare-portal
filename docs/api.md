# Контракт REST API

Все прикладные endpoint используют префикс `/api/v1`, JSON и время в ISO 8601 UTC. Ниже перечислены маршруты завершённого MVP.

## Маршруты MVP

| Метод и путь | Назначение | Этап |
|---|---|---:|
| `GET /api/health` | состояние каркаса backend | 1 |
| `POST /api/v1/auth/login` | вход | 2 |
| `POST /api/v1/auth/logout` | выход | 2 |
| `GET /api/v1/auth/csrf` | CSRF-токен для изменяющих запросов | 2 |
| `GET /api/v1/me` | текущий пользователь и права | 2 |
| `GET /api/v1/websites` | список сайтов | 2 |
| `POST /api/v1/websites` | добавить сайт | 2 |
| `GET /api/v1/websites/{id}` | карточка сайта | 2 |
| `PUT /api/v1/websites/{id}` | изменить сайт | 2 |
| `POST /api/v1/websites/{id}/audits` | запустить аудит | 3 |
| `GET /api/v1/audits` | история, пагинация и фильтр `websiteId` | 3 |
| `GET /api/v1/audits/{id}` | прогресс или итог | 3 |
| `GET /api/v1/audits/{id}/results` | страницы и проблемы с фильтрами | 4 |
| `GET /api/v1/websites/{id}/audit-comparison` | сравнение двух последних аудитов | 4 |
| `POST /api/v1/findings/{id}/tasks` | создать задачу | 4 |
| `GET /api/v1/tasks` | список задач | 4 |
| `GET /api/v1/tasks/{id}` | задача и история состояний | 4 |
| `PUT /api/v1/tasks/{id}` | приоритет, ответственный, статус | 4 |
| `GET /api/v1/dashboard` | агрегаты обзорной панели | 4 |
| `GET /api/v1/users` | список пользователей | 2 |

## Авторизация и права

Backend использует серверную сессию в HTTP-only cookie. Перед `POST`, `PUT`, `PATCH` и `DELETE` клиент получает CSRF-токен из `GET /api/v1/auth/csrf` и отправляет его в указанном ответом заголовке.

| Операция | ADMIN | SPECIALIST | VIEWER |
|---|:---:|:---:|:---:|
| Просмотр сайтов | да | да | да |
| Добавление и изменение сайтов | да | да | нет |
| Просмотр раздела «Команда» | да | нет | нет |
| Получение списка возможных ответственных | да | да | да |
| Запуск аудита | да | да | нет |
| Просмотр аудитов | да | да | да |
| Создание и изменение задач | да | да | нет |
| Просмотр задач | да | да | да |

## Сайты

Запрос создания и изменения:

```json
{
  "name": "Корпоративный сайт",
  "url": "https://example.com/",
  "maxPages": 50,
  "maxDepth": 2,
  "active": true
}
```

Backend нормализует URL и сохраняет `normalizedHost`. Разрешены только HTTP/HTTPS и стандартные порты; credentials и fragments запрещены. Домен разрешается через DNS, любой локальный, private, loopback, link-local, multicast или служебный адрес приводит к ответу `422`.

## Ответ асинхронного запуска

```json
{
  "id": "18ce7f17-74f3-4ef4-94f5-4d66df669dd8",
  "websiteId": "bb3a421c-a1d8-4e79-97da-d3d6d24b7ecf",
  "websiteName": "Корпоративный сайт",
  "status": "CREATED",
  "createdAt": "2026-07-28T18:00:00Z",
  "pagesDiscovered": 0,
  "pagesChecked": 0,
  "findingsCount": 0,
  "startedBy": "Анна Коваль"
}
```

Backend отвечает `202 Accepted`, а клиент получает прогресс периодическим `GET /api/v1/audits/{id}`.

## Результаты и сравнение

`GET /api/v1/audits/{id}/results` принимает необязательные параметры `severity`, `ruleCode`, `changeType` (`NEW`, `ONGOING`) и `query`. Ответ содержит сводку по важности, проверенные страницы, общее и отфильтрованное количество findings. Сравнение использует пару «нормализованный URL + fingerprint».

`GET /api/v1/websites/{id}/audit-comparison` возвращает два последних завершённых запуска, изменение оценки и три списка: `newFindings`, `ongoingFindings`, `fixedFindings`. Если завершён только один аудит, он считается базовым, а его проблемы — новыми.

## Задачи обслуживания

Создание задачи принимает необязательные `priority`, `assignedToUserId`, `dueAt`. Приоритет по умолчанию выводится из severity. Обновление через `PUT` передаёт `title`, `description`, `priority`, `status`, ответственного, срок и необязательный комментарий. Ответственным может быть только активный `ADMIN` или `SPECIALIST`; изменение статуса добавляет неизменяемую запись в `history`.

Фильтры списка задач: `status`, `priority`, `assignedToUserId`, `query`.

## Формат ошибки

```json
{
  "code": "WEBSITE_URL_NOT_ALLOWED",
  "message": "Этот адрес нельзя использовать для аудита.",
  "fieldErrors": [
    { "field": "url", "code": "PRIVATE_ADDRESS" }
  ],
  "correlationId": "01J4N7R8T9W2Y3Z4",
  "timestamp": "2026-07-28T18:01:04Z"
}
```

Статусы: `400` — формат запроса, `401` — не выполнен вход, `403` — недостаточно прав, `404` — объект отсутствует, `409` — конфликт состояния, `422` — URL синтаксически корректен, но запрещён политикой безопасности, `429` — лимит запусков, `500` — непредвиденная ошибка.

## Пагинация и фильтры

Списки используют `page` с нуля, `size` (максимум 100), `sort` и предметные фильтры. Ответ содержит `items`, `page`, `size`, `totalItems`, `totalPages`. Сортировка разрешена только по белому списку полей.

## Совместимость

- Изменения внутри `/api/v1` могут только добавлять необязательные поля.
- Удаление или смена значения поля требует нового префикса версии.
- Идентификаторы — UUID и не несут бизнес-смысла.
- Ответы не содержат password hash, внутренний IP проверяемого сайта или полное содержимое страницы.
