# Этап 5. Тестирование и передача

## Реализовано

- сохранены 14 быстрых unit-тест правил, сравнения и URL-политики;
- добавлен PostgreSQL integration-тест полного REST-сценария;
- подготовлены контролируемые страницы с HTTP 404, redirect, broken link, SEO- и accessibility-проблемами;
- добавлен отдельный `compose.test.yaml`, не использующий production-том;
- добавлен GitHub Actions workflow для backend, frontend, integration и Docker images;
- проверено применение всех миграций к пустой PostgreSQL 17;
- подготовлены установка, пользовательское руководство, тестирование и эксплуатация.

## Результат приёмки

Контролируемый аудит обходит четыре страницы и обнаруживает ожидаемые категории правил. Два запуска сравниваются как продолжающиеся проблемы; finding преобразуется в задачу, назначается специалисту и получает историю статусов. Повтор задачи отклоняется, `VIEWER` получает `403` на изменение.

Отдельный production smoke-запуск создаёт пустой том, применяет миграции V1–V3, создаёт роли и стартовые учётные записи, после чего frontend и health endpoint отвечают HTTP 200.

## Передача

Новому разработчику рекомендуется начать с `README.md` и `docs/installation.md`, затем запустить integration-контур по инструкции из `docs/testing.md`. Архитектурные границы описаны в `docs/architecture.md`, схема — в `docs/database.md`, API — в `docs/api.md`.

MVP соответствует девяти критериям общего плана. Функции за его пределами перечислены в `docs/requirements.md` и `docs/operations.md`.
